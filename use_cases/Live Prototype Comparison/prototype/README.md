# Dayline M0 产品原型

基于 `doc/PRD_CN.md` 制作的 Windows 桌面工作台可点击原型。当前不连接真实 Agent，界面中的任务、事件、产物、审批和连接状态均为合成演示数据。

用于外部 live research 的文件结构、URL、ready marker、fixture、安全边界和交互约定见
[PROTOTYPE_CONTRACT.md](PROTOTYPE_CONTRACT.md)。

## 产品结构

V2 是一个连续工作台，不再将 Review Queue 与 Workstream 做成两个跳转页面：

```text
Work（固定导航）
  ├─ 工作列表：需要你 / 执行中 / 全部
  └─ 选中任务：Result / Workstream / Context
       → 直接检查产物、差异、动作对象或澄清问题
       → 在当前任务中作出决定
       → 原地显示结果，列表计数同步更新
       → 手动选择下一项，不跳转模块、不弹返回选择框
```

- A/B/C 默认选中“需要你”筛选与一个具体任务，没有 `Open workspace` 中转按钮。D 直接打开完整状态看板，点击卡片展开同一套任务详情。
- 列表、全局导航始终保持稳定；切换任务保留各任务的页签、阅读位置和未提交草稿（当前会话内）。
- 验收后原地保留结果；已处理任务显示在列表的“刚刚处理”区域，不再计入待办。
- 修改要求必须填写具体反馈。可以通过明确标注的演示按钮模拟返回新版本；示例正文不会自动落实任意反馈。
- 授权与回执分离。点击授权只记录决定；只有主动生成模拟回执后才显示模拟交付。
- `Agents` 显示能力边界；`Activity` 可回到决定所属任务，不重放任何动作。
- 新建任务只创建本地草稿，不会启动真实 Agent。

## 视觉设计

A/B 使用暖白、黑灰与轻边框的克制风格：衬线标题、无渐变的图标与操作按钮、平面导航和任务列表。C 使用深绿导航、浅绿灰底板和绿色操作按钮，强调控制中心的分区与状态。D 使用浅蓝灰看板、状态圆点与独立任务卡，强调并行工作的流转。四版均不复制参考产品的品牌或素材，保留 V2 状态模型及本地存储，不重置任务数据。

### A / B / C / D 界面对比

标题栏的 **Design A / B / C / D** 切换呈现与浏览方式，不改变任务状态模型或决策语义：

| | A（保留原版） | B（更紧凑的成果视图） | C（控制中心） | D（状态看板） |
|---|---|---|---|---|
| 导航 | 图标与文字 | 紧凑图标栏，带悬停说明 | 深色横向导航 | 紧凑图标侧栏 |
| 工作概览 | 待办说明与执行中计数 | 待办说明与执行中计数 | 可点击状态卡，与列表筛选同步 | 三列状态与实时卡片计数 |
| 工作列表 | 默认展示摘要与 Agent | 标题优先；可开启摘要 | 独立任务卡片 | 需要你 / 执行中 / 已处理；草稿收进工具栏小入口 |
| 任务呈现 | 平面分栏、常规标题 | 独立阅读面板、衬线标题 | 冷绿底板、成果画布、分段页签 | 点击卡片展开详情，关闭后返回看板 |
| 操作位置 | 底部操作条 | 1280px 及以上在右侧 | 桌面端在成果上方；720px 及以下在底部 | 详情面板底部，保留验收与授权边界 |

四版使用同一详情组件和状态模型。任务、页签、已选产物版本和未提交反馈在即时切换时保留；在任一版本完成的决定在其他版本同样生效。A/B/C 的列表筛选在切到 D 后保留，D 展示三个工作状态列并沿用文本搜索；本地草稿通过独立小入口或全局任务搜索访问。为安全起见，接收对象、绑定版本、风险和影响说明不受摘要开关影响。

可直接用 `/?design=a`、`/?design=b`、`/?design=c` 或 `/?design=d` 打开；点击 A/B/C/D 后，选择保存在本机浏览器的 `dayline-design` 中。B 的摘要开关保留在当前会话中，不改任务数据。这里的 A/B/C/D 是同一个工作台的设计对比，不是早期 Workstream / Review Queue 两个功能的命名。C 的状态卡只改变现有列表筛选，不跳转任务、不启动 Agent。

#### D 的看板交互

- 直接打开 D 时展示“需要你 / 执行中 / 已处理”三列，优先呈现需要你处理的工作；从其他版本切到 D 时，保留当前任务并展开详情。
- 宽屏并排展示看板与详情；1100px 及以下用详情替换看板区域，可通过“返回看板”或 Escape 返回。关闭再打开会保留当前会话中的页签、阅读位置和草稿。
- 保留右上角“新建任务”。新建任务仍是本地草稿，不会启动 Agent，但不再占用独立看板列。有草稿时，工具栏显示紧凑的“草稿”计数按钮，点击展开小列表；无草稿则不显示该入口。已有草稿数据不删除。
- 工作卡片由既有状态自动分列，不提供拖拽绕过验收或授权。
- 修改要求进入“执行中”；模拟返回新版本后重新进入“需要你”；验收后进入“已处理”。
- 授权不等于交付，授权后仍在“执行中”等待回执。生成模拟回执后才进入“已处理”。
- “已处理”也包含拒绝发送，不代表全部已交付；卡片保留具体状态。确认研究范围后继续显示在“执行中”。
- 看板搜索筛选三个工作列，计数随搜索更新；不会关闭当前任务或清除未提交内容。草稿小列表独立于看板筛选，全局“搜索任务”仍可查找草稿。

用于外部研究时，可增加 `research=1`：

```text
/?design=a&research=1
/?design=b&research=1
/?design=c&research=1
/?design=d&research=1
```

研究模式固定 query 中指定的设计并隐藏页面内 A/B/C/D 切换器，防止参与者绕过研究工具的
版本切换。它不改变任务、内容、状态模型或决策操作。根节点上的
`data-prototype-ready="true"` 可用于确认界面已经完成初始化。

## 界面语言

原型支持 English 和简体中文。首次打开默认使用 English，可通过左侧“设置”切换；选择会保存在当前设备的浏览器存储中。

## 本地运行

```bash
npm install
npm run dev
```

生产构建：

```bash
npm run build
```

状态回归测试（Node 内置测试器）：

```bash
npm test
```

浏览器旅程测试（使用已安装的 Microsoft Edge）：

```bash
npm run test:ui
```

浏览器测试在独立上下文和 `127.0.0.1:4174` 服务运行，不改变开发预览中的数据。覆盖任务切换、反馈草稿、验收、返工版本、授权与回执、语言、持久化、1440/1024/820/390px 布局，以及主要正文和操作文字的对比度。

连续工作台旅程分别在 `design-a`、`design-b` 和 `design-c` 中运行，`design-d` 运行看板旅程；另验证四版状态一致、组件尺寸与操作位置的实际差异、B 的 1280px 侧栏断点、C 的状态卡，以及 D 的分列与自动流转、详情开关、键盘返回、搜索、草稿、双语、窄屏操作和文字对比度。

## 原型边界

- 所有外部动作均为前端模拟，不会发送消息、修改文件或调用真实 Agent。
- “批准”与“执行成功”在界面中保持分离。
- Observe、Delegate、Controlled 仅用于演示连接能力的差异化表达。
- 决定、反馈、版本和新建草稿保存在此浏览器的 `dayline-workbench-v2` 本地存储中，刷新后保留，不做跨设备同步。
- 文档预览、引用和执行记录均为合成示例，不伪装成真实文件或安全验证。
