# AI 任务委托纯问卷样例

[English](README.md) | [运行用例](../README.md) | [原生综合报告](report.md) | [逐题分布](distributions.json)

这是一场使用**固定20个授权合成 Persona**完成的纯问卷研究公开版。
本样例使用 **OpenRouter 的 `openai/gpt-6.1-terra`，温度1**和新的V3答题规则。
输入只有档案与中性假设概念，没有 prototype、产品观察、截图、Cards 或 Graph。

## 实际完成情况

| 项目 | 结果 |
|---|---|
| 问卷 | 12道题定义，含多选、带解释单选、矩阵和开放题 |
| 条件逻辑 | 愿考虑者回答首个任务，拒绝者回答拒绝原因 |
| 方法回答 | 20份有效，0无效、0缺失 |
| 题目位置 | 共240个：220个已回答，20个条件跳过 |
| 依据 | 220个答案均为 profile grounding，没有产品证据引用 |
| 分析 | 220/220有效答案已处理，8项发现、6项建议 |
| 产品交互 | 无环境构建、观察或动作 |
| 完整性 | 465个证据条目校验通过 |

本轮20个 Persona 全部选择“愿意考虑委托至少一个任务”，因此都回答了首个任务题，
都跳过拒绝原因题。没有为了填满分支而制造负面回答。
离线测试另外覆盖了拒绝、无法判断、档案不足及其正确分母。

模型输出均在首次校验通过，没有人工改答案、分析恢复或重启整场问卷。

## 主要描述性结果

| 问题 | 这组合成 Persona 的选择 |
|---|---|
| 生成但不发送／发布的草稿 | 20个接受在明确范围内无需逐次确认 |
| 修改现有文档 | 20个要求每次确认 |
| 向他人发送消息 | 20个要求每次确认 |
| 删除文件 | 19个要求每次确认，1个不委托删除 |
| 结果不确定时 | 17个先看不确定草稿，3个先停下询问，没有选中限额内继续 |
| 首次考虑场景 | 11个仅工作，7个仅个人，2个工作与个人都考虑 |

审批信息题中，内容／改动、接收方、权限范围和恢复选项均有20个选择；
理由与来源有13个选择，版本变化有18个选择，11个选择了全部6项。

[原生中文综合](report.md)将其解释为对可复核准备性协助的条件性开放，
而不是无限放权。建议是概念假设和验证方向，不能当作已观察到的产品缺陷，
也不能仅凭这些比例决定默认权限策略。

## 这次研究暴露的局限

- **天花板效应：** 20个都愿意条件性考虑，审批边界趋同；删除一项有1个更严格的拒绝意见。
  这不证明采用可能性，也不证明20个真人会独立形成相同共识。
- **信息选择不是排序：** 11个选中全部6项，多选题仍不能给这些信息排优先级。
- **不是独立真人判断：** 模型共同倾向、概念表述和相同问卷都可能促成答案趋同；
  完整处理不证明合成回答等同真人。
- **没有实际使用：** 不能据此证明可用性、收益、安全性、采用率、付费意愿或市场比例。
- **没有实际拒绝组：** 拒绝原因题是0已回答、20跳过，不是20个缺失或20个负面答案。
- **任务范围宽泛：** 任务相关不等于愿意委托，也不等于开发顺序。
- **后续问卷改进：** 可另行加入最重要项／强制取舍题和具体任务情境，提高区分度。
  本轮没有在看到结果后追改问卷或补造答案。

[逐题分布](distributions.json)保留各题已回答、跳过和无法支持的数量。
多选比例可以超过100%；确认边界矩阵是分类，不能求平均评分。
合并发现的支持人数也不代表每人同意正文每个子结论。
